
# 01. Azure Architecture Components

# Regions

- Regions consist of one or more geographically close data centers.
- Provide flexibility and scalability to reduce customer latency.
- Ensure data residency with a comprehensive set of compliance offerings.

Each region is composed of one or more **Availability Zones**.

# Region Pairs

- At least **300 miles (approximately 480 km)** of separation between paired regions.
- Automatic replication for selected Azure services.
- Region recovery is prioritized in the event of a regional outage.
- Platform updates are rolled out sequentially across paired regions to minimize downtime.

**Geo-Replication** → Replication of data from one Azure region to another.

# Availability Zones

Replication occurs **within the same Azure region**.

Each Availability Zone corresponds to one or more physically separate **data centers** within a region.

**Availability Zone = Data Center (DC)**

Each Azure region has **at least three Availability Zones**.

- Protect applications and data from data center failures.
- Physically separate data centers within the same region.
- Each data center has independent power, cooling, and networking.
- Connected through high-speed private fiber-optic networks.

# Azure Sovereign Regions (U.S. Government)

Designed to meet the security and compliance requirements of U.S. federal, state, and local government agencies, as well as their solution providers.

#### Azure Government

- A separate Azure cloud instance.
- Physically isolated from non-U.S. government Azure deployments.
- Accessible only to verified and authorized personnel.

# Azure Sovereign Regions (Azure China)

- Microsoft was the first foreign public cloud provider to operate in China in compliance with government regulations.
- Provides Azure China cloud services.
- A physically separate Azure cloud instance operated by **21Vianet**.
- All customer data remains within China to ensure regulatory compliance.
